## Introdução

Toda solução de Engenharia de Dados nasce de uma necessidade do negócio.

Antes de pensar em tecnologias, linguagens de programação ou bancos de dados, é preciso compreender qual problema a empresa deseja resolver.

Essa etapa é frequentemente ignorada, mas é ela que determina o sucesso ou o fracasso de um projeto.

Um Engenheiro de Dados que começa implementando uma solução sem entender o contexto corre o risco de entregar algo tecnicamente correto, porém sem valor para o negócio.

---

## O problema vem antes da tecnologia

É comum encontrar equipes discutindo ferramentas logo nas primeiras reuniões:

- Vamos usar SQL ou Python?
- Data Lake ou Data Warehouse?
- Databricks ou BigQuery?
- Batch ou Streaming?

Essas perguntas são importantes, mas não devem ser as primeiras.

A primeira pergunta sempre deve ser:

> **Qual problema estamos tentando resolver?**

Somente após compreender essa resposta é possível definir quais tecnologias fazem sentido para o projeto.



# 🧩 Estudo de Caso

Imagine novamente a empresa fictícia **CloudOffice**.

A diretoria percebeu que a quantidade de clientes cancelando suas assinaturas aumentou nos últimos meses.

Nesse momento, o problema não é criar um dashboard.

O problema também não é desenvolver uma pipeline.

O verdadeiro problema é responder perguntas como:

- Por que os clientes estão cancelando?
- Existe um perfil com maior índice de cancelamento?
- Em qual plano isso acontece com mais frequência?
- Em que momento da jornada ocorre o cancelamento?

Essas perguntas direcionam todo o restante do projeto.

---

## O papel do Engenheiro de Dados

Depois de compreender o problema, o Engenheiro de Dados começa a identificar quais informações serão necessárias para responder essas perguntas.

Nesse momento ele passa a investigar:

- Onde os dados estão armazenados.
- Quem é responsável por eles.
- Como são atualizados.
- Qual a qualidade dessas informações.
- Como disponibilizá-los para análise.

Observe que a tecnologia ainda não é o foco principal.

Ela será escolhida apenas quando o problema estiver claramente definido.

---

## Conclusão

Projetos de Engenharia de Dados não começam com código.

Eles começam entendendo um problema de negócio.

Quanto maior for essa compreensão, maiores serão as chances de construir uma solução simples, eficiente e capaz de gerar valor para a empresa.

Nos próximos capítulos veremos como entender o negócio, identificar os stakeholders e levantar os requisitos necessários para transformar esse problema em uma solução de dados.
