## Introdução

Nenhum projeto de Engenharia de Dados é desenvolvido para o próprio Engenheiro de Dados.

Toda solução existe para atender pessoas que precisam utilizar as informações geradas pelos dados. Essas pessoas são chamadas de **stakeholders**.

Identificar quem são os stakeholders é uma das primeiras atividades de qualquer projeto, pois são eles que definem necessidades, prioridades e expectativas sobre a solução que será construída.

Quando o Engenheiro de Dados entende quem são essas pessoas, ele consegue desenvolver produtos muito mais alinhados aos objetivos da empresa.

---

## O que são stakeholders?

Stakeholders são todas as pessoas ou áreas que possuem interesse direto ou indireto no projeto.

Eles podem fornecer informações, definir requisitos ou utilizar os dados produzidos pela solução.

Alguns exemplos são:

- Diretoria
- Gestores
- Analistas de Negócio
- Marketing
- Comercial
- Financeiro
- Produto
- Atendimento ao Cliente
- Engenharia de Dados
- Business Intelligence (BI)
- Ciência de Dados

Cada um possui uma visão diferente do mesmo problema.

---

## Por que conhecer os stakeholders?

Imagine desenvolver um dashboard extremamente completo para uma diretoria que deseja visualizar apenas cinco indicadores.

Ou construir uma pipeline complexa quando a área de negócio precisava apenas de um relatório simples.

Isso acontece quando o projeto é desenvolvido sem compreender quem utilizará o resultado.

Conhecer os stakeholders permite:

- Entender prioridades.
- Definir requisitos corretamente.
- Evitar funcionalidades desnecessárias.
- Melhorar a comunicação entre equipes.
- Entregar maior valor ao negócio.

---

## Estudo de Caso

Na **CloudOffice**, diferentes áreas participam do projeto.

### Diretoria

Deseja acompanhar a evolução do cancelamento de clientes.

### Marketing

Quer entender quais campanhas atraem clientes com maior permanência.

### Financeiro

Precisa calcular o impacto financeiro causado pelos cancelamentos.

### Produto

Busca identificar funcionalidades que aumentam a retenção dos clientes.

### Engenharia de Dados

É responsável por integrar, transformar e disponibilizar os dados necessários para todas essas áreas.

Embora todos estejam analisando o mesmo problema, cada stakeholder possui objetivos diferentes.

---

## O papel do Engenheiro de Dados

Um Engenheiro de Dados não trabalha isolado.

Grande parte do seu trabalho envolve comunicação.

É necessário conversar com diferentes áreas para compreender:

- Quais informações são importantes.
- Como essas informações serão utilizadas.
- Qual a frequência de atualização necessária.
- Qual o nível de detalhamento esperado.
- Quais indicadores são prioritários.

Essas conversas ajudam a transformar necessidades do negócio em requisitos técnicos.

---

## Conclusão

Conhecer os stakeholders significa compreender quem será beneficiado pela solução construída.

Quanto melhor o Engenheiro de Dados entender as necessidades dessas pessoas, maior será o valor entregue pelo projeto.

No próximo capítulo veremos como transformar essas necessidades em perguntas capazes de direcionar toda a solução.
