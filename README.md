## 📖 Sobre este projeto

A maioria dos projetos de Engenharia de Dados publicados no GitHub mostra apenas o resultado final: pipelines, consultas SQL, dashboards e arquiteturas.

Este manual segue uma proposta diferente.

O objetivo é apresentar **como um Engenheiro de Dados pensa antes de construir qualquer solução**, mostrando o caminho desde a compreensão do problema de negócio até a entrega de um produto de dados confiável.

Ao longo dos capítulos, será utilizado um estudo de caso fictício para demonstrar como decisões técnicas são tomadas com base nas necessidades do negócio.

---

## 🎯 Objetivos

- Demonstrar como projetos de dados realmente começam.
- Explicar a importância do entendimento do negócio.
- Apresentar o processo de descoberta de requisitos.
- Mostrar como decisões técnicas são tomadas.
- Conectar estratégia de negócio com implementação técnica.

# 🧭 Como utilizar este manual

Os capítulos foram organizados na mesma sequência encontrada em projetos reais de Engenharia de Dados.

Cada etapa depende da anterior, permitindo acompanhar toda a evolução de um projeto, desde a identificação de um problema de negócio até sua implementação.

---

# 💡 Filosofia do Manual

Antes de qualquer tecnologia, existe um problema.

Antes de qualquer pipeline, existe uma necessidade.

Antes de qualquer consulta SQL, existe uma pergunta de negócio.

Ferramentas evoluem.

Arquiteturas mudam.

Mas compreender o negócio continuará sendo a habilidade mais importante de qualquer Engenheiro de Dados.
